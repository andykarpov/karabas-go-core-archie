# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

An Acorn Archimedes core (A3xx / A4xx / A3000: ARM2, MEMC1a, VIDC1, IOC, 4 MB, RISC OS 3.11) for the Karabas Go, Mini and Mini G boards (Xilinx Spartan-6 XC6SLX25, ISE 14.7, XST): a port of the rtl of [Archie_MiSTer](https://github.com/MiSTer-devel/Archie_MiSTer) (the MiSTer port of Stephen J. Leary's Archie core of MiST).

Status: phase 1 done (Verilator model: RISC OS 3.11 boots to the desktop), next phase 2 (Mini G top). Docs, in Russian: `docs/PLAN.md` (research, decisions, phases). Follow the phases; record a changed decision in PLAN.md.

User decisions (2026-11-10): name `archie` (`archie.kg`, `/archie`), public repo, **video through a frame buffer** (one fixed output mode), RISC OS is a user file (no ROM in the repo or the `.kg`). All file work goes through the firmware (OSD, `FL` / `F` items, `img_sdc`): no loader or soft CPU in the core.

Templates: `../karabas-go-core-atarist` (sv2v flow, `fdc1772` with `img_sdc`, Makefile, sim harness), `../karabas-go-core-msx2` / `../karabas-go-core-pcxt` (SDRAM frame buffer), `modules/rtl/video/hdmi/kg_hdmi_ft_pll.v` (DCM_CLKGEN reprogramming: the VIDC pixel clock).

## Layout

- `src/Makefile`: the ISE flow, as in core-atarist (`make minig`, `make minig-xst`, `make minig-report`, `make archie-xst` = the machine alone, the fit check of Ф0, `make archie-report`).
- `src/make_core.py`: a symlink to `../../karabas-go-tools/make_core/make_core.py`. `src/tools/check_osd.py`: the slot check of `make core`.
- `src/core.json`: the core file description (kgo2, `archie.kg`).
- `src/rtl/`: the Archie_MiSTer rtl (import commit 92bd8e5, upstream commit in `upstream/SOURCE.txt`), changes marked `// karabas:`. `src/rtl/sv2v/`: generated by `src/tools/sv2v.sh` (one file per module, tops `archimedes_top`, `EEPROM_24C0x`): change the sources, run the script, commit both. `archie.prj` lists `rtl/sv2v`; `$readmem` paths are relative to `src/`.
- `src/rtl/karabas/`: our parts: `archie_kbd.v` (the keyboard protocol of mist-firmware archie.c in logic), `archie_cmos.v` (EEPROM_24C0x + `cmos.hex` from the MiSTer cmos.mif), `archie_ce.v` (VIDC pixel / audio enables from one clock, fractional: no clock per VIDC mode, the video goes to a frame buffer).
- `src/sim/run_boot.sh [--ms N] [--ppm PREFIX --every N] [--kbd] [--i2c] [--key MS:CODE[:HOLD]] [--pc-hist FROM] [--dump-ram] [--report MS] [--expect-*]`: Verilator model `sim_top.v` (the machine on one 42 MHz clock, a model of the wishbone side of the MiSTer sdram.v, the ROM at 0x400000) with the user's RISC OS (`~/Downloads/karabas-sd-archie/archie/riscos.rom`, never in the repo). 6..17 ms of machine time per second. `src/sim/run_checks.sh` (1 s, about a minute) and `--long` (the desktop at 5.1 s: many minutes, ask the user first). Start them with `job run` + Monitor on `job watch`; the scripts print `JOB-STAGE:` lines.
- `upstream/`: the MiSTer top `Archie.sv` and ReadMe: a reference for the wiring, not built.
- `modules/`: the git submodule [karabas-go-modules](https://github.com/andykarpov/karabas-go-modules). Clone with `--recursive`. A change to a module is made there (branch + PR) and taken here by moving the submodule commit.

## Rules of the core

The rules of core-atarist apply: standard video timing with syncs always present (the user's monitor rejects anything else), `FT_CLK_OUT` about 8 MHz on Mini / Mini G, Go `FDC_*` outputs 0 when unused, OSD switch index = item position unless `"index"`, an OSD value shows 10 characters at most, FL slots 0..7 only (one array with the F slots), Verilog-2001 for XST (`sv2v` for SV), imported code marked `// karabas:`.

- Mini / Mini G tops drive T3 (`FLASH_CS_N`) = 0: on Mini G2 it is the SDRAM ~CS.
- RISC OS and other Acorn ROMs are not ours: never in the repo or the `.kg`. The riscdevide ROM of the IDE podule comes with the upstream.
- XST silently removes a register with neither reset nor initial value whose way out of idle depends on itself (`sd_state` of `fdc1772`, fixed here as in atarist). When imported logic works in sim and not on the board, read the registers in the `.syr` (Xst:1710, 2404) first.
- XST cannot map a memory written by a part-select of a wide word (it hung over 30 min on `fdc1772_dpram`): one memory per byte lane.
- **Ask the user before every check on the board** (and the HDMI capture), even inside a phase. Ask before a firmware flash.
- One branch per phase of `docs/PLAN.md`, one PR at its end.
- Heavy builds: Mini G only while working on one feature, all boards for a release; map with cost table 2 first.
